How a paid request is checked

  1. No proof → HTTP 402 with a machine-readable price (click Request without proof on a listing).
  2. Pay on-chain from your own account: buy_access (paywall, subscription) or buy_credits (metered), and wait for finalization.
  3. Prove you control the buyer account: the gateway issues a single-use challenge that expires after two minutes and names the listing, your address, the gateway, the contract and the chain. Your wallet signs it. A transaction hash and an address are public, so they are not accepted as proof; a used or expired challenge is rejected.
  4. Access and consumption on-chain: the gateway reads has_access. For metered and subscription listings it then consumes one credit with use_call and waits for that transaction to be finalized with a successful result. Only then is the data released. No gateway key, a failed or reverted consumption: no data. Requests for the same buyer and listing run one at a time.
